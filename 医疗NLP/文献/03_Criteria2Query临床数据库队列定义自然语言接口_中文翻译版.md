# Criteria2Query：临床数据库队列定义自然语言接口 中文翻译版

原文题名：Criteria2Query: a natural language interface to clinical databases for cohort definition

## 中文题名

Criteria2Query：用于临床数据库队列定义的自然语言接口

## 摘要翻译

队列定义是临床研究中的瓶颈，通常依赖领域专家的主观判断。数据驱动的队列定义很有吸引力，但它需要研究者熟悉医学术语体系和临床数据模型。

Criteria2Query 是一个自然语言接口，用于支持人机协作完成队列定义，并在临床数据库中执行查询。

该系统使用混合信息抽取管线，结合机器学习和规则方法来系统解析 eligibility criteria 文本。它先把文本转换为结构化筛选标准表示，再转换成符合 OMOP Common Data Model 的 SQL 查询。用户可以在 ATLAS Web 应用中交互式地审查、修改和执行查询。

实验中，Criteria2Query 在实体识别上取得 0.795 的 F1，在关系抽取上取得 0.805 的 F1。否定检测、逻辑检测、实体标准化和属性标准化的准确率分别为 0.984、0.864、0.514 和 0.793。全自动生成查询平均每条标准耗时 1.22 秒。

## 方法翻译

Criteria2Query 的核心流程是：

1. 解析自由文本筛选标准。
2. 识别临床实体和属性。
3. 识别否定和逻辑。
4. 做概念标准化。
5. 生成结构化表示。
6. 转换成可执行 SQL 查询。
7. 允许用户在界面中检查和调整。

它强调“全自动”和“人机协作”两种模式。全自动用于快速生成初稿，人机协作用于修正复杂情况。

## 结果翻译

系统在实体识别、关系抽取、否定检测和逻辑检测方面取得了较好的结果，但概念标准化仍然比较困难。这说明把自然语言映射到标准医学概念，是临床 NLP 中长期存在的难点。

## 对 CHIP2026 的启发

Criteria2Query 和 CHIP2026 的目标非常像，只是输出不同。

Criteria2Query：

```text
筛选标准文本 → 结构化表示 → SQL 查询
```

CHIP2026：

```text
筛选标准文本 + 患者文本 → FHIR resources → FHIR service 查询
```

可借鉴点：

1. 先生成结构化中间表示，不要直接从原文跳到 FHIR。
2. 中间表示可以包含：实体、数值、单位、时间、否定、逻辑。
3. 对复杂题允许半自动：LLM 生成初稿，人再校验。
4. 以“可执行”为核心，而不是只追求语言理解。

大白话：

> 先把句子翻译成机器看得懂的条件表，再把条件表翻译成 FHIR。

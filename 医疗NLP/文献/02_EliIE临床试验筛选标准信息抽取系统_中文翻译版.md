# EliIE：临床试验筛选标准信息抽取系统 中文翻译版

原文题名：EliIE: An open-source information extraction system for clinical trial eligibility criteria

## 中文题名

EliIE：一个用于临床试验筛选标准的信息抽取开源系统

## 摘要翻译

研究目标是开发一个开源信息抽取系统 EliIE，用来解析和形式化自由文本临床研究筛选标准。系统面向 OMOP Common Data Model 5.0。

EliIE 的处理流程分为四步：

1. 临床实体和属性识别。
2. 否定检测。
3. 关系抽取。
4. 概念标准化和结构化输出。

研究人员和领域专家共同设计了标注规范，并为 230 个阿尔茨海默病临床试验创建了筛选标准标注语料，其中包括 8008 个实体、3550 个属性和 3529 个关系。这些筛选标准被表示为针对 OMOP CDM 的查询。

实验结果显示，实体识别最佳 F1 为 0.79，关系抽取最佳 F1 为 0.89，否定检测准确率为 0.94，端到端查询形式化准确率为 0.71。

## 方法翻译

EliIE 把筛选标准从自然语言转成结构化查询，核心是一个分层管线。

第一步，识别临床实体和属性。实体可以是疾病、药物、检查、治疗等；属性可以是严重程度、数值、时间、频率等。

第二步，做否定检测。比如“无糖尿病史”“否认高血压”不能简单因为出现疾病词就判断患者有病。

第三步，做关系抽取。比如“血红蛋白 ≥ 90 g/L”中，血红蛋白、数值 90、单位 g/L、大于等于之间必须连接起来。

第四步，做概念标准化和结构化输出。也就是把文本里的说法映射到标准数据模型中。

## 结果翻译

EliIE 的结果说明，筛选标准解析不能只靠命名实体识别。单独识别出实体只是第一步，真正难点在于：

1. 否定词。
2. 数值范围。
3. 时间约束。
4. 实体之间的关系。
5. 最终能不能形成可执行查询。

## 对 CHIP2026 的启发

CHIP2026 的 `NLP_CODE` 可以借鉴 EliIE 的四步管线。

建议我们的代码也拆成：

1. `extract_entities`：抽疾病、检查、治疗、症状、数值、时间。
2. `detect_negation`：处理无、未见、否认、不伴有。
3. `extract_relations`：把检查名和数值阈值、疾病和状态、治疗和时间连接起来。
4. `build_fhir_resources`：生成 FHIR resources。

大白话：

> 不要把所有东西写成一坨正则。先找词，再看否定，再连关系，最后生成 FHIR。

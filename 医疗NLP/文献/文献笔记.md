# CHIP2026 医学 NLP 相关文献笔记

本文档汇总 5 篇与临床试验筛选标准解析、患者筛选、信息抽取、查询生成相关的论文，并重点说明它们对 CHIP2026 医学 NLP 比赛的启发。

---

## 1. Chia：大型临床试验筛选标准标注语料库

英文题名：Chia, a large annotated corpus of clinical trial eligibility criteria

### 这篇在讲什么

Chia 是一个大规模临床试验 eligibility criteria 标注语料库。它从 ClinicalTrials.gov 的 1000 个 IV 期干预性试验中抽取筛选标准，标注实体和关系，并把每条标准表示为有向无环图。

### 关键数据

- 12409 条筛选标准
- 41487 个实体
- 15 种实体类型
- 25017 个关系
- 12 种关系类型

### 核心思想

筛选标准不能只看成一段文本，而应该拆成：

- 实体：疾病、检查、药物、手术、数值、时间
- 属性：严重程度、单位、范围、状态
- 关系：大于、小于、发生于、合并、否定
- 逻辑：AND、OR、NOT

### 对 CHIP2026 的启发

CHIP2026 的 `question` 可以先拆成结构化条件，再生成 FHIR resources。

建议我们为每道题建立中间表示：

```text
{
  "entities": [],
  "attributes": [],
  "relations": [],
  "logic": []
}
```

大白话：

> 先把医生那句话拆成“有什么东西、它有什么数值或状态、它和别的东西是什么关系”，再写代码。

## 2. EliIE：临床试验筛选标准信息抽取系统

英文题名：EliIE: An open-source information extraction system for clinical trial eligibility criteria

### 这篇在讲什么

EliIE 是一个开源系统，用来把自由文本筛选标准解析并形式化成 OMOP CDM 查询。

### 核心流程

1. 临床实体和属性识别。
2. 否定检测。
3. 关系抽取。
4. 概念标准化和结构化输出。

### 关键结果

- 实体识别 F1：0.79
- 关系抽取 F1：0.89
- 否定检测准确率：0.94
- 端到端查询形式化准确率：0.71

### 对 CHIP2026 的启发

我们的 `NLP_CODE` 也应该拆成类似管线：

```text
extract_entities
detect_negation
extract_relations
build_fhir_resources
```

特别重要的是否定检测：

- 否认糖尿病史
- 无高血压
- 未见明显肝肾功能异常
- 不吸烟

大白话：

> 看到关键词不等于患者符合，必须看它是不是被否定了。

## 3. Criteria2Query：临床数据库队列定义自然语言接口

英文题名：Criteria2Query: a natural language interface to clinical databases for cohort definition

### 这篇在讲什么

Criteria2Query 把临床试验筛选标准从自然语言转换成可以在临床数据库中执行的查询。它结合机器学习和规则方法，先生成结构化表示，再生成 SQL 查询，并支持用户在 ATLAS 中检查和修改。

### 核心流程

```text
筛选标准文本
  ↓
实体和属性识别
  ↓
否定和逻辑检测
  ↓
标准化
  ↓
结构化条件
  ↓
SQL 查询
```

### 关键结果

- 实体识别 F1：0.795
- 关系抽取 F1：0.805
- 否定检测准确率：0.984
- 逻辑检测准确率：0.864
- 平均自动查询生成时间：1.22 秒/条

### 对 CHIP2026 的启发

CHIP2026 和 Criteria2Query 的区别是输出形式：

```text
Criteria2Query：筛选标准 → SQL 查询
CHIP2026：筛选标准 + 病历 → FHIR resources → FHIR 查询
```

但中间步骤非常相似。

建议我们也做一个中间层，不要直接从原文跳到 FHIR：

```text
question_parse_result
  -> target_resource
  -> required_fields
  -> fhir_resource_builder
```

大白话：

> 先把题目翻译成条件表，再把条件表翻译成 FHIR。

## 4. Transformer NER：基于 Transformer 的筛选标准实体识别

英文题名：Transformer-Based Named Entity Recognition for Parsing Clinical Trial Eligibility Criteria

### 这篇在讲什么

这篇文章比较 BERT、ALBERT、RoBERTa、ELECTRA 等 Transformer 模型在临床试验 eligibility criteria 命名实体识别上的效果。

### 关键发现

在 MIMIC-III 临床笔记和 eligibility criteria 上预训练的 RoBERTa 表现最好：

- Chia 数据严格/宽松 F1：0.658 / 0.798
- FRD 数据严格/宽松 F1：0.785 / 0.916

### 对 CHIP2026 的启发

NER 可以帮助我们找：

- 疾病
- 症状
- 检查指标
- 手术
- 药物
- 数值
- 时间

但 NER 不是终点。CHIP2026 最终考的是：

1. 生成 FHIR resources。
2. 查询代码能查到。
3. 最终患者结果正确。

大白话：

> 模型负责帮你圈词，但真正比赛得分靠的是后面怎么组织 FHIR 和查询。

## 5. Criteria2Query 3.0：大语言模型用于筛选标准查询生成

英文题名：Criteria2Query 3.0: Leveraging Generative Large Language Models for Clinical Trial Eligibility Query Generation

### 这篇在讲什么

这篇文章研究如何用生成式大语言模型帮助生成临床试验 eligibility criteria 查询。它属于 Criteria2Query 路线的新版本，重点是 LLM 在查询生成和人机协作中的作用。

### 核心思想

LLM 可以帮助完成：

1. 理解复杂筛选标准。
2. 拆解医学条件。
3. 生成结构化中间表示。
4. 生成查询代码或查询草稿。
5. 辅助人工检查。

但 LLM 也有风险：

1. 可能编造字段。
2. 可能生成不可运行代码。
3. 可能忽略数据模型约束。
4. 可能输出看起来合理但查询不到结果的内容。

### 对 CHIP2026 的启发

CHIP2026 明确支持基于大语言模型生成 FHIR Bundle。我们的策略可以是：

```text
LLM 读 question / FHIR_FSH
  ↓
LLM 生成 NLP_CODE 初稿
  ↓
程序做语法和格式检查
  ↓
人工对齐 FHIR_SERVICE_CODE
  ↓
打包提交
```

大白话：

> LLM 可以帮忙写初稿，但必须用程序和查询代码验货。

## 6. 五篇文献合在一起给我们的比赛方法

综合五篇文献，最适合当前比赛的路线是：

```text
规则 baseline
  + 类别模板
  + 结构化中间表示
  + 否定/时间/数值处理
  + FHIR_SERVICE_CODE 反向校验
  + LLM 辅助生成和审查
```

### 建议工程管线

```text
读取测试集 question / FHIR_FSH / FHIR_SERVICE_CODE
  ↓
解析 question，形成中间条件
  ↓
根据 label 选择类别模板
  ↓
解析患者文本主题片段
  ↓
抽取实体、数值、时间、否定、关系
  ↓
生成对应 FHIR resources
  ↓
用查询代码期待的字段反向检查
  ↓
base64 编码 NLP_CODE
  ↓
打包成 FHIR Bundle message
```

### 最重要的比赛原则

1. 不要把题目当 17 分类。
2. 不要只做 NER。
3. 不要只看医学含义，要看查询代码怎么查。
4. 优先保证所有题可运行。
5. 对否定、时间、数值和单位单独写通用函数。
6. LLM 可以帮忙，但最终必须用代码验证。

### 今天开始应该做的事

从训练集第一条开始，逐行拆：

1. `question` 在问什么。
2. `FHIR_FSH` 定义了什么 Profile。
3. `NLP_CODE` 生成了什么 Resource。
4. `FHIR_SERVICE_CODE` 查询什么字段。
5. 为什么这些字段能查到正确患者。

大白话：

> 先学会完整拆一题，再复制这个拆法处理 A 榜和 B 榜。
